# SUMMARY.md 编写指南（AI用版）

> 适用场景：收到一份 `CHANGELOG.md` 与一份“原版流派请教表格汇总”后，产出一份用于给他人快速浏览数据包改动内容的总览文件 `SUMMARY.md`。
> 唯一数值信源：bwiki（https://wiki.biligame.com/mcs/）。CHANGELOG 未提到的字段一律视为原版不变，不写入 SUMMARY。

---

## 一、输入材料与职责

| 材料                 | 用途                                                         |
| -------------------- | ------------------------------------------------------------ |
| `CHANGELOG.md`       | 改动事实的唯一来源：改了哪些数据、改成了什么。               |
| 原版流派请教表格汇总 | 推断“请教途径”的最低境界。表格按流派分行，每行一个境界层级，列出该层级的神通与功法（含 ID）。 |
| bwiki                | 核对原版数值，判断条目属于哪种改动类型；补全展示所需但 CHANGELOG 未列出的原版字段（如品阶、属性、悟道需求、修炼速度、价格、驱阵消耗）。 |

---

## 二、输出文件整体结构

```
# [Mod 名称]改动汇总

> 更新于版本`vX.Y.Z`

[toc]

---

## 功法

### `改动类型` 名称
（属性字段）
（表格）

---

## 神通

### `改动类型` 名称
...

---

## Buff

### `改动类型` 名称
**改动**：…

---

## 杂项

* 不属于以上分类的改动，逐条列出。
```

- 标题下固定一行 `> 更新于版本\`vX.Y.Z\``，版本号取 CHANGELOG 最新版本，便于日后查阅文件对应的 Mod 进度。
- 段落顺序固定：功法 → 神通 → Buff → 杂项。没有内容的段落直接省略，不保留空标题。
- 每个条目用三级标题，标题格式严格为：``### `改动类型` 名称``。
- 条目之间先列 `新增`/`获取补充`/`重做`，再列 `修改`；同类内按品阶从高到低或 CHANGELOG 出现顺序，全文保持一致。

---

## 三、改动类型标签

只使用以下四个标签：

| 标签       | 判定条件                                                     |
| ---------- | ------------------------------------------------------------ |
| `新增`     | 原版不存在该 ID 的数据，本数据包首次创建。                   |
| `修改`     | 原版存在该 ID 且玩家有正常获取途径，本数据包调整了其数值、效果或获取方式。 |
| `获取补充` | 原版数据完整存在，但玩家没有任何正常获取渠道（含仅商店/仅 Boss 专属、无请教），本数据包补入了获取/请教途径。 |
| `重做`     | 原版仅有美术资源或残缺数据、没有实际效果或无法正常使用，本数据包将其重做为可用内容。 |

判定优先级：原版是否存在 → 玩家能否获取 → 是否有实际效果。三者都满足才是 `修改`。

**关键澄清**：原版已有任何正常获取途径（商店兑换、任务奖励、NPC 请教等），即使本包新增了另一条获取/请教渠道，也归为 `修改`；只有原版完全无法正常获取、本包才补入正常获取流程时，才用 `获取补充`。

**双标签**：同一条目在同一版本内既有数值改动、又补入了原版不存在的获取渠道时，标题写 ``### `修改`/`获取补充` 名称``，两个标签并列。

## 四、条目属性字段

### 4.1 字段与顺序

按以下顺序排列，**只写该条目实际有、且属于关注重点的字段**，没有的直接省略整行：

```
**标签**：`CHANGELOG分类`/`数据ID名`
**品阶**：X阶X
**属性**：水 / 金 / 剑 / 水、剑 / 阵法、剑、水
**消耗**：N\*`五行`+M\*`五行`（仅神通）
**悟道需求**：X（X）、X（X）
**获取途径**：非兑换途径与请教途径的获取方式（例如剧情任务）
**请教途径**：具体NPC（境界及以上）
**兑换途径**：地点（价格货币）
```

### 4.2 字段取值规范

- **标签**：前半段是 CHANGELOG 标题中的分类名（如 `星河水剑`、`金虹蓄势`、`杂项雾剑`），不是流派名；后半段是数据文件名或内部 ID（如 `金虹剑诀_天阶`）。不确定后半段就只写分类。
- **品阶**：`天阶上`…`人阶下`。品阶被改动时写 `地阶上（原为地阶下）`。
- **属性**：bwiki 标注的功法/神通属性，多项用顿号分隔，如 `水、剑`、`阵法、剑、水`。CHANGELOG 未改动属性时照抄原版；不确定就留空并询问用户。
- **悟道需求**：直接写单字种类＋括号水平，如 `木（融会贯通）`、`阵（初窥门径）`；不写“木之道”“阵道”等全称，多项用顿号分隔，等级用游戏内原文。
- **价格与货币换算**：依照用户提供的货币名称与兑换比例编写；格式 `地点（N货币单位）`；CHANGELOG 中明确标注的，除非用户特意指正否则始终优先采用 CHANGELOG 的结论。
- **请教途径**：只写“改动分类对应的 NPC 类型（境界及以上）”，如 `竹山叠毒NPC（筑基中期及以上）`、`星河剑派水剑NPC（金丹初期及以上）`。**不展开具体 NPC 名字，不逐个列入特殊 NPC**；特殊途径确实无法归入流派时，只写 NPC 类型或名字、不写境界。不得笼统写“某派全体修士”，除非 CHANGELOG 明确说明该改动对全流派生效。

### 4.3 阵法驱阵的补充字段

阵法类神通（带“阵”属性、可驱阵的技能）在条目的主表格之后，**额外补充三项驱阵信息，只写这三项**：

```
**驱阵消耗**：N\*`五行`+M\*`五行`
**驱阵属性**：原属性将“阵”替换为“气”
| 层级 | 驱阵效果 |
|---|---|
| 炼气期 | … |
| 筑基期 | … |
| 金丹期 | … |
| 元婴期 | … |
| 化神期 | … |
```

- **驱阵消耗**：查 bwiki 对应「阵法名-驱」页面。页面消耗栏只渲染灵气图标，AI 读不到图标对应的五行，只能读到数量（如 `x2`、`x1` 加图标）。**五行必须由用户提供，或用带 `alt` 的页面源码确认，严禁凭本体属性推断。**
- **驱阵属性**：把原属性中的“阵”字替换为“气”，其余保留。如 `阵法、木` → `气、木`；`阵法` → `气`；`阵法、剑、水` → `气、剑、水`。
- **驱阵效果**：默认按模板逐层书写，每个境界相同：`【后继无力】驱动一次【阵法名】。` 若 CHANGELOG 明确改动了驱阵效果，按 CHANGELOG 写。
- **驱阵没有**悟道需求、获取途径、请教途径、兑换途径，这些字段一律不写。

## 五、请教境界推断规则

**优先级 1：CHANGELOG 明确说明。** 写了“XX 境界及以上可请教”“在 XX 境界学习第 N 层”，直接采用。

**优先级 2：流派表格首次出现层级。** 在表格中找到目标神通/功法在目标流派里**第一次出现**的那一行，该行境界即最低请教境界。规则为“首次出现后，此境界及以后均可请教”。

**优先级 3：不确定就不写境界。** 条目只出现在“废弃”“待替换”段落、流派名与条目明显不匹配、或表格中无该流派时，请教途径只写流派/NPC 名字，不写境界。

**境界写法**：具体到前中后期。1～15 级对应炼气、筑基、金丹、元婴、化神各前中后期（如筑基中期、金丹初期），统一写 `XX及以上`，不写 `最低XX`，不写大境界笼统写法。

**特殊 NPC：** wiki 指出的特殊途径默认为使用表格记载流派中某流派的 NPC，归入对应流派写；不单独展开特殊 NPC 名单。“废弃”“待替换”条目一律忽略。

## 六、表格规范

### 6.1 列结构

- **功法**：`层级 | 修炼速度 | 效果`
- **神通**：`层级 | 效果`；若消耗被改动，增加一列 `层级 | 消耗 | 效果`。
- **Buff**：不建表格，用一行 `**改动**：…` 说明。
- **阵法驱阵**：独立一张 `层级 | 驱阵效果` 表，见 6.4。

### 6.2 行结构

- 功法按五层逐行，层级列写 `第一层`～`第五层`。
- 神通按境界逐行，层级列写 `炼气期`～`化神期`。
- 禁止 `1/2/3/4/5` 或 `8/14/23/39/78` 的合并写法，每层数值单独成行。
- 不写“境界”列，境界已体现在层级列。

### 6.3 数值与格式

- 乘号统一 `\*`，防止被解析为斜体。
- 消耗格式：`5\*`金``，多色用 `+` 连接。
- 效果文案贴近 CHANGELOG 原文，只做标点统一。
- 每行完整复述整句效果，不用“同上”“以此类推”。

### 6.4 阵法驱阵补充

见 4.3。要点复述：

- 驱阵只在主表格之后补 **驱阵消耗、驱阵属性、驱阵效果表** 三项，不写悟道/获取/请教/兑换。
- 驱阵效果默认模板：每层 `【后继无力】驱动一次【阵法名】。`，CHANGELOG 改动则按 CHANGELOG。
- 驱阵消耗五行以用户提供或 `alt` 文本为准，不靠图标推断。

## 七、内容取舍原则

1. **只写改动后的内容。** 未提到的字段视为原版不变，不出现、不声明。
2. **跨版本合并。** 同一数据多版本改动只写最终状态，不出现版本号。
3. **`**改动**` 行只用于 Buff 类修改。** 功法和神通的改动直接体现在表格数值中，不额外加说明行。唯一的例外是改动涉及 Buff 层面、无法用表格表达时（如“战斗中 Buff 显示仅占用一个图标位，实际效果不变”），可在该条目内用一行 `**改动**：…` 说明。
4. **原版对照只在必要时出现。** 如 `品阶：地阶上（原为地阶下）`、`**改动**：伤害类型由剑系调整为金剑系`。整段原版效果对比不写入。
5. **不写 `>` 引用附注。** 原版来源、补入渠道等背景信息在标签、获取/请教/兑换字段中已能体现，不再用 blockquote 重复说明。
6. **不确定的字段宁可不写。** 尤其请教境界、悟道需求、价格、属性、驱阵消耗；写错比不写更糟，拿不准就直接问用户。
7. **删除类改动用文字说明。** Next 不支持数据删除，`**改动**` 行文字交代即可。
8. **Buff 段落的取舍。** 具体效果改动（如伤害类型变更）必须列出；CHANGELOG 只写“新增 N 个用于加强 XX 的 Buff”且无具体效果时，可用一行简写或按用户要求省略。
9. **不得虚构查证过程。** 未实际读取页面内容时，不得声称“已从 bwiki 核对”；凭记忆填写的字段应在交付时标注“未实际查证”或直接询问用户。

## 十、边界情况备忘

- **CHANGELOG 只说“调整数值”没给新数值**：不从 bwiki 反推，改为在 `**改动**` 行写“数值已调整，具体以数据文件为准”，或直接询问用户。
- **条目在流派表格中找不到**：请教途径只写流派名不写境界；连流派都判断不了就只写“原版途径”。
- **同时改品阶和效果**：品阶写 `新阶（原为旧阶）`，效果按最终状态逐层写。
- **属性不确定**：留空并在交付时单独列出待确认项，不自行猜测。
- **驱阵消耗图标读不出五行**：页面消耗栏是渲染后的图标，AI 只能读到数量。五行必须问用户，或让用户贴含 `alt` 的源码片段，严禁按本体属性推断。
- **驱阵效果与模板不符**：bwiki 页面若有独立的逐层数值（非“驱动一次”），先向用户确认是沿用页面数值还是按模板写，不要自行取舍。
- **Buff 类改动**：只写 `**改动**：…` 一行，不建表格；有层数或数值时在行内用 `\*` 转义列出。
- **杂项段**：NPC 流派配置调整（化神领域变更、首个功法变更等）归入杂项，每条一行 `*`，不建表格。
- **Wiki 查不到的小阶功法修炼速度**：可参考同阶同类型功法（如人阶中功法参考问水剑典），并在交付时说明依据。
